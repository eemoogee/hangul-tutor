# 난 direct reassembly study

This is a separate, unscored prototype beside the preserved [Relief-Exploded Syllable Study](../relief-exploded-syllable-study/NOTES.md). It tests one task: **난 → open → lift final ㄴ → return ㄴ → 난**. The earlier V1/V2/V3 page and all production files remain unchanged. Open [index.html](index.html) directly in a modern browser, or serve this folder with a static HTTP server for phone testing. No framework, backend, curriculum, saved learner state, or network asset is required.

## Controls

1. Tap the syllable stage or **Open 난** to separate its three jamo.
2. Tap the visible final ㄴ or **Lift final ㄴ**. Its outline expands from a compact context form to a standalone-like ㄴ. The initial ㄴ and ㅏ do not move during this lift.
3. Tap the lifted ㄴ again, tap its outlined lower slot, or activate either labelled return control. Optional dragging follows the piece: release within 38 SVG units of the slot to place it. A farther release returns to the lifted state and gives explicit feedback. Merely approaching the slot never finishes the task; a valid release or tap is required.
4. **Undo** steps back from completion to lifted, lifted to open, or open to assembled. **Reset** restores the printed syllable. The keyboard route uses Enter or Space on the stage, final ㄴ, slot, or labelled buttons. The optional drag is unavailable with reduced motion; tap controls remain usable.

Switch between **Flat morph** and **Relief morph** at any state. Both use the same SVG front paths, directions, timings, distances, selection color, and placement logic. The relief treatment adds eight offset side copies, a restrained contact ellipse, and up to 32 px of forward CSS Z translation for the selected final ㄴ. These cues are bundled, so this comparison does not isolate which cue contributes most to perceived depth. All letter faces stay front-facing. Only the selected piece moves during lifting. The 3D wrappers remain unflattened (`overflow: visible`, no ancestor `filter` or reduced opacity), and each wrapper contains one SVG component. The moving transparent hit box is 64 × 64 SVG units, at least 44 × 44 CSS pixels at both tested widths.

## Geometry and type

The jamo centerlines and fixed point order are adapted from the preserved relief study, which in turn builds on [Exploding Syllable v2](../exploding-syllable-v2/GEOMETRY.md). The two ㄴ pieces have distinct packed proportions and identities. Their standalone target uses one common 98 × 112 SVG-unit L. The ㅏ keeps its two rectangular subpaths. Every form has the same path structure and point order, so intermediate coordinates interpolate without a topology swap. These are hand-authored, typeface-specific teaching vectors, not extracted Noto glyph outlines, a universal Hangul construction rule, or handwriting stroke order.

Opening moves the pieces 42 units in the earlier study's directions. The final ㄴ grows only partway toward its standalone shape during opening, then finishes that expansion during the learner's lift. During return, the upper pieces pass continuously through the **나** context coordinates before compressing into their **난** context coordinates as the final ㄴ nears the slot. The returning piece independently morphs from standalone-like to compact final form. This makes the upper components' accommodation visible; the exact intermediate composition is a visualization, not a printed glyph. A short easing overshoot supplies one restrained settle, then the page remains still.

The assembled endpoint is real Unicode **난** in locally bundled **Noto Sans KR Variable**, regular weight. The font file is an unmodified copy from the official [Noto CJK KR subset release](https://github.com/notofonts/noto-cjk/blob/main/Sans/Variable/TTF/Subset/NotoSansKR-VF.ttf), 10,415,420 bytes, SHA-256 `9E1D729E7E2B36F9EF439DA102F8C134C10AABE46F1C843BF0ACA5C043B86F76`. Its copyright and SIL Open Font License 1.1 are in [OFL.txt](OFL.txt), from the official [Google Fonts Noto Sans KR license](https://github.com/google/fonts/blob/main/ofl/notosanskr/OFL.txt). This bundled face prevents silent phone substitution; the page reports a load failure. A local file viewer or local HTTP server must allow the relative font request. The full font adds about 10 MB to this prototype; it has not been subset further.

After the authored SVG settles, its visible face fades to printed 난 over 120 ms. Opening reverses that handoff. Noto's optical stroke edges and the authored square-ended geometry still differ, so a small shape and position discontinuity is visible at the endpoint, especially in the initial ㄴ. The bundled font removes device-to-device **font selection** as a variable; it does not make the SVG a literal Noto outline. Keep the font file and OFL together when sharing the study.

## Browser verification

Run `node --check app.js` and `verify.py` with Python Playwright and installed Chromium. The verifier writes [captures](captures/) and checks both treatments at **390 × 844** and **320 × 568** with simulated touch: bundled font loading; matched front paths; direct tap-to-lift and tap-to-return; direct slot tap; optional valid and invalid dragging; upper-piece anchoring during lift; return morph and seating; undo/reset; moving hit boxes and minimum target size; keyboard controls; reduced-motion simulation and system preference; no page/console errors, stage clipping, or horizontal scrolling. Run `make_strips.py` with Pillow to rebuild the compact review strips from the stage captures. The captured intermediate drag and return frames are checked visually as well as by assertions. These are browser checks, not physical Android or learner results.

The [flat](captures/flat-390-sequence.png) and [relief](captures/relief-390-sequence.png) frame strips show assembled, open, lifted, approaching, at slot, seating, and completed states. [390 px completed](captures/relief-390-09-complete.png) and [320 px lifted](captures/relief-320-02-lifted.png) show the page layout. At 320 px, the page scrolls vertically to reach controls; nothing depends on hover or continuous animation.

## Remaining phone and learner checks

- On the owner's Android phone, check whether the bundled font loads over the chosen local server and whether the printed 난 remains readable at 320 px. Observe the 120 ms SVG-to-font handoff and note any distracting change of stroke position or weight.
- Check touch precision while final ㄴ moves, direct tapping of its slot, accidental page scrolling during drag, dropped frames, and depth rendering in Android Chrome. Check screen-reader announcements and at least one other browser engine separately.
- Compare flat and relief on the same device with equivalent tasks. Ask beginners how many pieces make 난, which two pieces are the same letter, and how the final consonant changes the upper region. Record first attempts, hesitation, confusion, and reconstruction before treating the metaphor as educationally useful. A small session can guide design, not prove improved learning.

The current spring and slot threshold still feel partly mechanical: release near the slot triggers an automatic final settle, and the SVG-to-font handoff remains visible. The relief makes the lifted piece easier to distinguish visually, but it also darkens the narrow final stroke; whether that helps beginners is untested. The page is for owner and tester review only.
