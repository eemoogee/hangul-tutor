# Syllable Swap — input comparison

An isolated, single-file study of **Tap** and **Drag** replacement. Open `index.html` directly in a current browser, preferably Chrome on Android. Its SVG letter outlines are embedded; the Google-hosted IBM Plex UI font is optional and falls back to installed fonts offline. No build, server, account, or network connection is required for the interaction. A static 나 remains visible with a browser-requirement note if JavaScript is disabled or fails before the interactive stage builds. Successful startup removes that fallback from the DOM. Owner Android captures of the prior build showed duplicate letter shapes consistent with the fallback remaining visible after its `hidden` attribute was set; the phone DOM was not inspected directly.

## Source and scope

The visual and animation baseline is the user-supplied **Syllable Swap Study.html** export from 2026-10-20 (SHA-256 `F94D38C949342D1B17B3D6E3092219BF64481AC4C4691A39BB610C0260366F20`). See `docs/prototypes/syllable-swap-study/VERSIONS.md` for that history. The later export puts cross-fading outlines in separate SVG layers to avoid a reported solid-square paint issue; this study keeps that fix. The source copies remain untouched by this comparison. The original's 16 syllables, eight tray letters, Noto Sans CJK KR Bold outlines, gradients, thickness, shadows, timing options, optional arrival squash, and return-home animation are carried into both modes through one `swap` function. No new letters or effects were added.

## Try it

1. Open the syllable and select its consonant or vowel, either on the stage or with the buttons below it.
2. Choose **Tap** or **Drag** under **Developer input mode**. Tap a tray letter in Tap mode. In Drag mode, drag a tray letter onto the selected letter's slot. The small dragged letter follows the pointer with a 52 px upward offset so the destination stays visible.
3. An invalid drop returns the tray letter and leaves the syllable unchanged. **Undo** restores the preceding syllable; **Reset to 나** clears swap history. Both modes use the same valid-swap animation function and timing settings. The dragged piece starts its landing animation from its release position; a tapped piece starts at the tray.
4. For keyboard, switch, or other non-drag input in Drag mode, select **Use tap alternative**, then use tray buttons. Keyboard activation of tray buttons also works directly. The selected component can be reached with the labeled consonant/vowel buttons.

At widths up to 420 px, the same eight tray letters form two rows so every button stays at least 44 × 44 px. The moving letter is attached to the captured pointer, and the destination is measured from the selected piece's current screen position with a generous hit region. Touch dragging disables native panning over the tray; ordinary page scrolling elsewhere remains available.

## Evaluation protocol

Open **Session notes** and enter a task label such as “change 나 to 노”; do not enter names or identifiers. Start the task before the interaction. A successful swap records input mode, input path, task, starting and ending syllables, completion, invalid-attempt count, elapsed milliseconds, and whether help was required. Reset, changing modes, or starting another task records the active task as incomplete. These observations stay in page memory; **Download observations** exports JSON on demand. Reload clears them. Do not use the log as a learner score.

Alternate mode order between participants. Use comparable swaps in each condition, reset to 나 between tasks, and record discoverability, satisfaction, and preference separately in observation notes. The explicit tap alternative should be logged as such when it is used in the Drag condition. No personal identifiers are needed.

## Local verification on 2026-10-20

Headless Chrome mobile emulation tested 390 × 844 and 320 × 568, with normal and reduced-motion settings. All four runs showed two SVG glyph paths on load, no horizontal overflow, 44 px tray targets, a successful tap on a component while it was moving, Tap `나 → 다`, Undo `다 → 나`, invalid Drag release leaving `나`, valid Drag `나 → 노`, and the tap alternative `나 → 노`. No page errors occurred. A simulated 320 px touch stream verified that pointer cancellation leaves `나` and removes the temporary piece, while a valid touch drag reaches `노` with zero page-scroll change. Rapid Tap attempts during an active swap were ignored; subsequent `다 → 마` succeeded. Keyboard activation in Drag mode produced `나 → 바`. The anonymous task log captured mode, completion, elapsed time, and help state. See the endpoint and mid-drag captures in `captures/`.

Reduced motion removes the CSS tray pulse and transition and collapses JavaScript tween durations and delays. The resulting state changes were checked in the simulated browser. A JavaScript-disabled load showed the two static fallback paths and explanatory note; the interactive load removed them. Physical Android rendering, touch accuracy, browser file handling, and perceived ease of use remain owner/tester checks, including confirmation that the overlapping fallback is gone. The CSS/JS differences inherent to a dragged starting position and a direct pointer path are uncontrolled input consequences; the completed swap's shapes, shading, effects, timing, and outgoing return path are shared. The external UI font may look different without network access; embedded SVG letters do not depend on it.
