# Vowel Transfer Lab v2.2 — eight-item assessment (portable package)

A self-contained, offline, single-page assessment for the Hangul Tutor
project. No network, no build step, no runtime dependencies, no participant
data. Built to be opened or served and reviewed as-is.

**Status:** never played by a learner. Not phone-tested. Not deployed.
Not reviewed by a Korean-language reader.

---

## Contents

| File | What it is |
| --- | --- |
| `index-v2.html` | The whole assessment. One file. All shapes are inline SVG; there are no images, fonts, external scripts, or network calls to load. |
| `REPORT-v2.2.md` | Design record: what changed, corrected probability analysis, disclosed weaknesses, verification results, observation protocol. |
| `verify_transfer_lab_v2.py` | Adversarial browser verifier. 22 checks. Plays 9 adversaries x 200 seeded sessions in Chromium. |
| `model_baselines_v2.json` | Modeled baselines from 50,000 simulated sessions per adversary. Referenced by the report's probability table. |
| `RUN-VERIFICATION.txt` | Captured output of the verifier run performed against these exact packaged files. |
| `SHA256SUMS.txt` | SHA-256 of every file in this package. |

There are **no local assets**. `index-v2.html` contains no `src`, `href`,
`url()`, `@import`, or `fetch` reference of any kind — checked with `grep`,
not assumed. Opening the file directly from disk works.

## Run it

### Simplest: open the file

Double-click `index-v2.html`, or:

```bash
# Windows (git-bash or cmd)
start index-v2.html

# macOS
open index-v2.html

# Linux
xdg-open index-v2.html
```

Fully functional from `file://`. No server needed.

### Serving it (recommended for a phone)

A `file://` page is awkward to reach from a phone, so serve the folder. Bind
to all interfaces only on a network you trust.

```bash
# from the folder containing index-v2.html
python -m http.server 8756 --bind 0.0.0.0
```

Then open, substituting the host machine's LAN address:

```
http://<host-lan-ip>:8756/index-v2.html
```

Find the address with `ipconfig` (Windows) or `ip addr` / `ifconfig`.

The assessment makes **no** network requests; the server only delivers the
single file.

## Verify it

### Requirements

```bash
python -m pip install playwright
python -m playwright install chromium
```

Verified with Python 3.11 and Playwright on Windows. The verifier starts its
own HTTP server on an ephemeral port, so nothing needs to be running first
and port conflicts cannot occur.

### Run the verifier

```bash
# from this folder
python verify_transfer_lab_v2.py
```

Expected: `22/22 checks passed`. Exit code 0 on success, 1 on any failure.
Takes roughly 2–4 minutes (1,800 seeded sessions played in a real browser).

It writes `.verify_out/verify_transfer_lab_v2.json` containing every check and
every adversary's score distribution.

### What the verifier proves, and what it does not

It proves, against the real page in a real browser:

- the bank is 2 visual / 4 sound-to-shape / 2 syllable, with cues a, eo, o, u
  present exactly once in every one of 240 generated sessions
- the correct answer's display position spans all four slots for every item
  and stays inside 15–35% per slot
- each abstract visual item offers no option already displayed elsewhere in
  that item (the "missing fourth symbol" shortcut is gone), and the two
  items' glyph pools are disjoint from each other
- the third family uses ㅁ only, with no ㄴ distractor
- the same seed reproduces an identical session; a different seed does not
- no non-learned strategy exceeds chance-level 4/8, except a single-surface-cue
  learner at 34.5%, which is partial knowledge rather than a shortcut

It does **not** establish that any learner learns anything. It is a check on
the instrument, not a result. See the "What is NOT verified" section of
`REPORT-v2.2.md`.

## Scoring, in one paragraph

Three subscores are reported separately; there is no total and no pass/fail
threshold anywhere in the code. The two abstract-shape items are a
visual-analogy calibration measure and carry no Hangul-literacy claim. The
four sound-to-shape items are scored on the committed choice, with the first
pick, every preview change, and the final commit logged separately so that
immediate recognition can be distinguished from self-correction. The two
ㅁ items are encoding and decoding, presented in a randomized order.

## Data handling

Nothing leaves the device. Sessions are stored in the browser's
`localStorage` under `vowelTransferLab.sessions.v2` and leave it only when a
tester presses "Copy report" or "Download report". This package contains
**no** participant, tester, or session records. The `.verify_out/*-report.json`
files produced during development were generated by scripted adversaries and
are deliberately excluded from the ZIP.

## Reproducing a session

Enter a seed in Tester setup before starting. The seed is stored in the
report, and `buildPlan(seed)` in the page regenerates the identical item
order, cue assignment, option order, and keys. Every session is reproducible
from its seed plus the `itemSetVersion` (`transfer-lab-v2.2-eight`).
